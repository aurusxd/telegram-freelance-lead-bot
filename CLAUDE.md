# CLAUDE.md

Прочитай `tech.md` в корне репозитория целиком, прежде чем писать код. Это единственное ядро проекта: стек, схема БД, контракты discovery-конвейера, LLM-контракты, структура папок, конвенции коммитов, Definition of Done и дорожная карта по стадиям.

Подчиняйся `tech.md` дословно.

- Контракты (схема БД, DTO, интерфейсы провайдеров, форматы ответов LLM) не выдумывай. Если нужного контракта в `tech.md` нет — остановись и выдай блок:

  ```
  CONTRACT GAP
  Что нужно: ...
  Зачем: ...
  Предлагаемая форма: ...
  ```

  Не пиши код с придуманным типом. Дождись обновления `tech.md` (append, бамп версии) прежде чем продолжать работу над этим контрактом.

- Реализуй одну задачу за раз из дорожной карты `tech.md` (раздел 14), отдавай сфокусированный дифф, а не всё приложение сразу.
- Стадия 1 (скелет) должна быть полностью пройдена и чек-лист «скелет готов» — зелёным, прежде чем начинать любую задачу стадии 2.
- Каждая фича стадии 2 повторяет структуру эталонной вертикали — синка `sources.json` (service → repository → db), см. раздел 3, 8.1 и 14 `tech.md`.
- Дефолтные мониторимые чаты владелец вносит через `sources.json` в корне репозитория (раздел 8.1 `tech.md`), формат `[{"handle": "@...", "title": "...", "enabled": true}]`. Не путать с `/add_chat` — это точечное добавление в рантайме, `sources.json` — декларативный источник, синкается на старте бота.
- Миграции — только `alembic revision --autogenerate` от `db/models.py`, в том же коммите, что меняет модели.
- Тесты — из критериев приёмки задачи, не из реализации (раздел 12 `tech.md`): контрактные на стыках, идемпотентность, путь ошибки, property-based там, где есть чистая логика. Ни один тест не ходит в реальный Telegram/DeepSeek/GitHub/SearXNG — только фейки за интерфейсами.
- **Обязательно.** Модуль релевантности (`llm/relevance.py`, `services/lead_service.py`, `discovery/pipeline.py`) должен быть покрыт набором тестов на фейковых сообщениях из фикстуры `tests/unit/fixtures/relevance_messages.py` (раздел 12.1 `tech.md`) — явно релевантные, явно нерелевантные, пограничные и мусорные кейсы, проверка правильной ветки (создан Lead/DiscoveredChat и уведомление отправлено — или нет). Без этого набора задача не считается закрытой.
- Definition of Done: `ruff check` чист, `pyright` чист, `pytest` зелёный, миграция приложена при изменении схемы, `.env.example` обновлён при новой переменной, секреты не закоммичены.
- Коммиты — Conventional Commits, на английском, маленькими логическими шагами по ходу работы (раздел 13 `tech.md`).
- Секреты только через `.env`, никогда не логировать значения токенов/ключей.
- **Код без комментариев.** Никаких `#`-комментариев и docstring-простыней в коде проекта, кроме `# type: ignore[код]` в крайнем случае и служебных конфиг-файлов (`.env.example`, `docker-compose.yml`, `alembic.ini`), где комментарий — часть формата. Если шаг требует пояснения — вынеси его в функцию с говорящим именем.
